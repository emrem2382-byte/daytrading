# Скенер за интрадей сигнали - GitHub Actions версия

Тича безплатно в GitHub Actions на всеки 5 минути (04:00-16:00 ч. нюйоркско
време, делници), праща BUY сигнали и затворени позиции (TP/SL) в Telegram,
пази история в `signals_log.csv` вътре в самия repo.

## Еднократна настройка (~5 минути)

### 1. Качи тези файлове в нов GitHub repo
- Влез в [github.com](https://github.com) → New repository (може да е **private**, безплатно е).
- Качи всички файлове от тази папка (включително скритата папка `.github/`).

### 2. Добави двата "тайни" параметъра
В repo-то: **Settings → Secrets and variables → Actions → New repository secret**

Добави тези два отделни secrets:
| Име | Стойност |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токенът на твоя бот от @BotFather |
| `TELEGRAM_CHAT_ID` | твоят Telegram chat ID |

*(Щом вече имаш бот, тези две неща вече би трябвало да ги имаш от настройката му.)*

### 3. Тествай ръчно
- В repo-то: таб **Actions** → избери "Intraday Stock Scanner" → бутон **Run workflow** (горе вдясно).
- Изчакай ~1 минута, провери дали дойде съобщение в Telegram (или поне логовете в Actions да минат без грешка).

### 4. Готово
Оттам нататък cron-ът сам ще го пуска на всеки 5 минути през делници.
Няма какво друго да правиш - CSV логът (`signals_log.csv`) и състоянието
(`state.json`) се обновяват и запазват автоматично обратно в repo-то след
всяко пускане.

## Важно

- **Безплатно е** - GitHub Actions дава щедри безплатни минути месечно, а
  скриптът тича само по няколко секунди на пускане.
- GitHub-ският cron **не е прецизен до минута** - при натоварване сигналът
  може да закъснее с няколко минути. За информационни сигнали е напълно
  приемливо.
- Ако 60 дни не мине никакъв commit в repo-то, GitHub временно спира
  scheduled workflow-и - но понеже скриптът сам си прави commit на всяко
  пускане през делник, това не би трябвало да е проблем.
- Логиката на самия сигнал (EMA9/EMA20 + обем + VWAP) е абсолютно същата
  като в Colab версията - нищо стратегическо не е променено, само начинът
  на изпълнение.
